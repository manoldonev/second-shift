# second-shift review-context SECTION catalog — the machine-readable source of truth for
# the named H2 sections the shipped reviewers key on in a consumer's
# .claude/second-shift/review-context.md (and the per-reviewer review-context/<reviewer>.md
# files). check-review-context-sections.sh lints a consumer's headings against this list;
# docs/extension-points.md "Authoring the review-context surface" is the human-readable
# mirror. A release selftest (check-review-context-sections-selftest.sh, the lockstep case)
# fails if the catalog's active names and the docs template diverge.
#
# Format (pipe-separated, one section per line):
#   <section-name> | <comma-separated readers> | <status> [| <file>]
#     status = active                       (a live catalog section)
#            | deprecated-alias-of:<name>   (a drifted spelling; <name> must be an active row)
#   readers = effective-registry reviewer names (no plugin: prefix), the sentinel `all`
#             (every panel reviewer reads it, via review-lead), or a declared reader token.
#   file    = review-context.md (the default when the column is absent; it covers the
#             per-reviewer review-context/<reviewer>.md too) | intake-context.md (#1032).
#
# DECLARED READER TOKENS. A reader that is not a reviewer is declared on a line of its own,
#   reader: <token> | <what reads the section>
# so the coverage line names it when its section is absent, rather than filtering it out as an
# unknown reviewer. docs/extension-points.md "Authoring the intake-context surface" is the
# human-readable mirror of the intake-context.md rows. review-lead itself is such a reader: it
# is the orchestrator, not a member of the effective registry it dispatches from.
#
# WHAT A READER TOKEN MEANS. A reviewer name here names the DIMENSION the section calibrates —
# not a guarantee that a subagent of that name is dispatched to read it. review-lead reviews
# several dimensions in-session (its lead pass) instead of spawning them, and the lead pass loads
# the same shared file and the same per-reviewer review-context/<name>.md those reviewers used to
# self-load. Read every row as "this section calibrates that dimension, applied by whoever reviews
# it this round" — the spawned reviewer where one is dispatched, the lead pass otherwise. The
# tokens stay reviewer names because those names remain effective-registry members and the
# format's legal column values are registry names or `all`; a section whose reader is a lead-pass
# dimension is not a section with no reader. The lane's review session dispatches none of these
# reviewers: it reads the shared review-context.md itself, as one reviewer over every dimension,
# and never the per-reviewer files.
#
# H1 title lines (`# ...`) are NEVER linted — only H2 (`## ...`) headings (H3+ subsection headings are section content). Sibling
# discipline to the doctor's extension-manifest.txt (EP-3). Additions/renames are breaking-class:
# check against known-consumer headings before release and list them in the release
# What-breaks body (docs/releasing.md).

## Considered and cleared

- **Nested terminal lines cannot leak into the log.** The discriminator would be defeated if a killer suite's own output reached `sweep.log`: `tools/mutation-sweep-selftest.sh` invokes the sweep 102 times, so a merge touching `tools/mutation-sweep.sh` would run nested sweeps whose `timing:` / `FATAL:` lines would suppress the bound-kill branch on exactly the widest merges — and the real log the build tested against never reached that guard, so its evidence could not have covered this. Falsified two ways: every nested invocation captures output (`OUT="$( … 2>&1 )"`), and the real `sweep.log` contains **one** line that is not the sweep's own (`diff base:`, the step's echo) and **zero** killer-suite output — the sweep surfaces only its own `early exit (first 'FAIL:' line…)` summaries. My own full selftest sweep log likewise carries 0 of each line.
- **The sizing comment's "reached ~80% of that work in its 60 minutes"** reads as impossible against the cost model (60 min × 2 workers = 7,200 worker-seconds, against 10,481 claimed) and `scope-completeness-reviewer` suppressed it at confidence 72 for that reason. It is sound: 13,116 is explicitly the cost with *nothing exiting early*, and the real log is full of `early exit (first 'FAIL:' line, scored as KILLED) … the remaining cases were not run` — a killed mutant costs a fraction of its suite. The bound is therefore worst-case sized, which errs long, which is the safe direction for the property AC-1 is protecting.
- **"No observed re-run duration appears in the diff"** (suppressed at 70). AC-1 asks for a bound sized from a measured re-run of the scope, not for an observed wall-clock time: the re-run supplies the scope (374 mutants, reproduced from CI's log above) and `tools/selftest-suite-timings.tsv` supplies the CI-measured per-suite seconds. Both halves are measurements, and the comment names both.
- **Injection surface of the new interpolations.** `GRADED` is a `grep -c` count, digits only; `SWEEP_STEP_TIMEOUT_MIN` is a workflow literal. The un-randomized `MUTATION_MERGE_BODY` heredoc delimiter and log-derived `SURV`/`OTHER` are pre-existing and unchanged. `permissions:` unchanged (`contents: read` on `sweep`, `issues: write` only on `file-red`); trigger is still `push: branches: [main]`.
- **Test coverage.** Nothing asserts the job > step relation, the single-sited bound, or the branch ordering that AC-3 rests on. D-8 ratifies "no new script/guard/selftest" inside this fence, so the absence is a decided out-of-scope rather than a new gap. The bound's single-siting is closed by construction (one value, read twice) rather than by a test, which is the stronger form; the branch ordering is not.
- **`pr-gates` red.** Its only failure is `✗ no committed verdict record (a file named *-842-lean-verdict.md)` — the expected pre-verdict state this record resolves. `mutation-sweep-pr` passed; `lint-and-selftests` and `selftests (macos, bash 3.2)` were still pending, which is why AC-4 was executed here rather than cited.

## Strengths

- **The discriminator is read off the subject, not guessed at.** GitHub exposes no "this step timed out" signal to a later step, and rather than inferring one the change keys on a property the sweep itself guarantees — `finish()` as the printing exit path, `die()` as the loud one — and states why in the comment. It is also the same property `COMPLETE_MARKER` already asserts, so the lane gained no second notion of "did this finish".
- **The branch order is the substantive fix, not the prose.** Testing the bound kill ahead of the survivor branch is what stops a run cancelled mid-scope from filing under a key that asserts a graded verdict; keeping its partial survivor ids under a heading that says they are partial is the right resolution of the tension rather than dropping them.
- **The bound is a derivation from committed figures, and it says which ones.** 9,964 of 13,116 attributed to one guard's 47 mutants against a 212 s suite, with the consequence stated — "this is really that one guard's bound, and it moves when that suite's cost moves". Every anchor figure reproduces.
- **The unverifiable part is flagged as unverifiable.** `timeout-minutes: ${{ fromJSON(env.…) }}` cannot be exercised before merge on a `push: main`-only workflow, and the PR says so instead of implying a test that does not exist.
